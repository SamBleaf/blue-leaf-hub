## 3. Enable, prerequisites, rollback

1. **Review + merge** the branch (owner).
2. **Apply migration 206** in the Supabase SQL editor (production). It is additive and idempotent (re-applied cleanly in tests). It creates the private `takeoff-exports` bucket.
   Verify read-only afterwards: `node scripts/takeoff/probe-live-schema.mjs` → mig-206 rows should flip to PRESENT; and in SQL:
   `SELECT has_function_privilege('anon','public.takeoff_commit(uuid,integer,jsonb,jsonb,text)','EXECUTE');` → `false`.
3. Railway: set **`TAKEOFF_ENABLED=true`** (API). No other env vars. (Optional `LATO_TTF_PATH` is honoured by the PDF like `poPdfKit`.)
4. Real-device gate (§6) on an installed iPhone before telling crews.
5. **Rollback:** unset `TAKEOFF_ENABLED` → every takeoff endpoint returns 404 FEATURE_DISABLED and the Takeoffs buttons disappear. Plans, takeoffs, exports and placement history stay in the database. **Do not drop the takeoff tables** once they hold job evidence. The plan-lifecycle fixes in `workforceRoutes.mjs` are independent of the flag and safe before or after 206.

Before 206 is applied the existing plan features keep working (proven: `takeoff-premigration` 5/5) and takeoff endpoints say "Takeoffs need database migration 206" (503 MIGRATION_PENDING).

## 6b. Independent adversarial review (2026-10-13) — all findings addressed

| # | Finding | Fix |
|---|---|---|
| 1 HIGH | A shrunk requirement locked out every later placement | guard only judges the (contribution, length) pairs the new placement allocates; regression tests SQL + API |
| 2 HIGH | Concurrent "Retry PDF" could leave a ready export with no bytes | per-attempt object path (no upsert), conditional ready-claim, loser removes only its own files; race test |
| 3 | Lost save response looked like someone else's edit | unanswered batch is resent unchanged (same key + base revision) |
| 4 | Profile-less items merged into one order line | grouping key includes the item name when there's no drawn profile |
| 5 | Touching an endpoint jumped it ~40 px | drag keeps the grab offset, 3 px slop, no-op touch commits nothing |
| 6 | Plan bytes behind measurements could be repointed | identity trigger on hash-anchored `job_documents`; viewer refuses bytes that differ from the calibrated hash |
| 7 | Free-text role could double-count a measurement | role is `primary` only (server + CHECK); unique active (measurement, material) |
| 8 | Long-profile PDF pagination; fractional mm rounded | dimension list continues below the drawing; label reprinted on continued lists; values exact to 0.01 mm |
| 9 | Plan replaced mid-export could still freeze | replacing/archiving a plan bumps the takeoff revision; company freshness checked at freeze |
| 10 | Plan upload could supersede a non-plan | refused (RPC + fallback) |
| 11 | Placement replay didn't check the key's action | checked |
| 12 | Supplier contacts hidden in API but printed on worker PDF | policy: leading hands see the order contact (name/email/phone) — never account terms or notes |
| 13 | Unbounded arrays / page index | per-save caps, page index < 10,000, legacy-size check before download |
| 14 | Mirrored part split into two lines; float noise | key canonical over reverse + mirror (same straight part turned end-for-end), rounded |
| 15 | Re-scale review missing | old-scale runs flagged + **Review with new scale** (before → after, choose runs); check must be a different dimension; supersede per region |
| 16 | Tender job delete could half-run into takeoff FK | guard: "This job has takeoffs … Archive it instead" |
| 17 | Old plan download signed any document | restricted to plan types (staff + worker) |

## 7. Deviations, known issues, owner decisions

- Release-one methods: `flashing_runs@1` (runs + counts/manual on a flashing material) and `finished_piece_count@1`; later methods are contract-tested only and not offered in the UI.
- Recovery writes immediately after every completed edit; an edit made within a few milliseconds of the app being killed can still be lost (browser storage commit window). Documented in SOP 20-07.
- The service worker's `autoUpdate` can reload an open editor; nothing is lost because recovery is already written, and the user is offered Restore.
- Existing platform risk (not introduced here): `job_documents` has an `auth_users` RLS policy allowing any authenticated user (including portal clients) to read rows via REST. Generated order PDFs are registered there as `management` documents; their bytes stay in a private bucket. Tightening `job_documents` RLS belongs to the portal security work.
- Out of scope, raised as a separate task: material-PO route selects `suppliers.address`, which does not exist in production.
- Bestimator span-table defect (T48 `9005`) untouched — still to be checked upstream against the source table.
- Split is offered for measured runs only; a counted/manual length over the ceiling is fixed by entering shorter finished lengths.
- Not built (later): "recent items" in Choose material; a worker-app sign-out (worker drafts expire after 7 days or on save/discard).
- On a phone at fit-to-page, a printed dimension is only a few dozen pixels long: tapping its ends without zooming can miss by enough to fail the 0.5% independent check (it correctly stays Needs review). The calibration screen tells people to zoom in on each end; a magnifier loupe would make this easier (not built).
- The save pill shows **Not synced** for the 500 ms autosave debounce after each edit, then Saving… → Saved. Honest per §11, but it flickers amber while measuring.
- `.github/workflows/takeoff.yml` is written but not committed — the repo's `.gitignore` keeps `.github/workflows/` out of commits ("commit separately with a workflow-scoped token"); CI has therefore never run.
- `SOP_INDEX.md` header total and the folder lists in `SOP_MAINTENANCE.md`/`CLAUDE.md` don't yet mention `20_takeoff` (append-only edits this round).
