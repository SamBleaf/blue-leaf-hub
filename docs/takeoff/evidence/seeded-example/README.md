# Seeded example takeoff — synthetic plan, real server

Everything here was produced by `scripts/takeoff/seed-example.mjs` calling the **real takeoff HTTP API** of the local
sandbox (real server code, real SQL on an isolated Postgres 17, real pdfkit PDFs). No production service, no customer data.

```bash
npm run takeoff:sandbox -- --reset src/ui-review/fixtures/takeoff/synthetic-plan-set.pdf   # terminal 1
node scripts/takeoff/seed-example.mjs docs/takeoff/evidence/seeded-example                   # terminal 2
```

## The plan

`src/ui-review/fixtures/takeoff/synthetic-plan-set.pdf` (12 pages, generated by `scripts/takeoff/make-review-fixtures.mjs`).
Its known geometry is in `synthetic-plan-set.json`.

- Page 1 is a 1:100 A4 sheet with a 12,000 × 8,000 building outline. It has printed 12,000 / 8,000 / 3,000 dimensions.
  1 mm on site = 0.028346 PDF units, so 1 PDF unit = 35.2778 mm.
- Page 2 is the same drawing with `/Rotate 90` and an offset crop box (`viewBox [30, -40, 872, 555]`).
  It proves that rotation and crop are handled.
- Pages 3–12 are dense A1 pages, used to test thumbnails, memory and render performance.

## What the seed exercises

| Area | What was done | Where to see it |
|---|---|---|
| Two-axis calibration | Page 1: horizontal 12,000 + vertical 8,000 (agree → uniform), independent 3,000 check → **ready** | `workspace-snapshot.json` → `calibrations[0]` |
| Rotated page | Page 2 (`/Rotate 90`, offset crop): screen-horizontal = PDF vertical; calibrated **ready** | `calibrations[1]`; run `rotated` measures 4,312 → 4,600 like page 1 |
| Flashing profiles | Apron: 3 legs, 90°/−90°, closed hem 10 mm. Barge: 4 legs incl. 135°, open return 15 mm start, closed hem 12.5 mm end, coated face right | `materials[]`; drawn on `FO-001001-export-2.pdf` |
| Company standard | "Std valley gutter (example)" saved as a company preset, then copied into the job (independent copy) | `materials[2]` has its own id; preset unchanged |
| Measured runs | 4,312 → 4,600; connected corner 3,000 → 3,200; 4,200 → 4,400 (raw + 200, rounded up to 100) | `computed-schedule.json` → `contributions` |
| Long piece | 5,900 → 6,100 (> 6,000) → **handling flag**, still orderable | schedule line `LONG`; PDF "Long piece — handle with care" |
| Over ceiling → split | 8,801 → 9,100 (> 9,000) **blocks the order** until split 4,600 + 4,600 − lap 100 = 9,100 | `contributions[5].split` |
| Explicit split | 7,000 → 7,200 split 3,700 + 3,700 − lap 200 = 7,200 (no second allowance) | `contributions[4].split` |
| Counted lengths | 4 taps at finished 2,400 (no allowance) | `measurements` kind `count` |
| Manual finished pieces | 6 × 300 stop ends, pieces-only material (`finished_piece_count@1`) | `measurements` kind `manual` |
| Worker actor | Runs, counts and manual pieces were committed through the **Worker** API as a leading hand | sandbox DB: `select kind, created_by_type, count(*) from takeoff_measurements group by 1,2` → run/count/manual = `employee` (the snapshot JSON does not carry actor columns) |
| Orders | FO-001001: draft export 1 → order-ready export 2 → recorded **placed** (SO-EXAMPLE-1) | `orders-and-status.json` |
| Cancellation | FO-001002 (pickup): exported, placed, then **cancelled** with a reason → its 6 stop ends show as remaining again | `orderStatus` |
| Frozen exports | Each PDF footer carries the calc version and the snapshot sha256 prefix | PDF footers |

## Files

- `FO-001001-export-1-DRAFT.pdf`, `FO-001001-export-2.pdf`, `FO-001002-export-1.pdf` — actual server-generated supplier PDFs
- `workspace-snapshot.json` — the stored workspace (calibrations, materials, measurements, contributions)
- `computed-schedule.json` — shared calculator output (schedule lines, contributions, splits, problems)
- `orders-and-status.json` — orders, exports, placements, required/ordered/remaining
- `SUMMARY.txt` — the console summary from the seed run
