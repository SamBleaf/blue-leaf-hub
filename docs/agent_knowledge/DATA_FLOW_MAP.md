# Blue Leaf Hub — Data Flow Map

> Last updated: 2026-05-21

---

## Primary Lifecycle Flow

```
ENQUIRY
  ├── User creates Lead in Sales Pipeline
  │   Tables: leads, lead_activities
  │   Data created: name, contact, project type, budget, timeline, source
  │   AI: Blueprint coaching, transcript analysis
  │
  ▼
QUALIFICATION
  ├── APB scorecard completed
  │   Tables: lead_qualifying_scores
  │   Data created: weighted scores across 8 dimensions
  │
  ▼
DISCOVERY / WINNING OFFER
  ├── Meetings logged, Blueprint coached
  │   Tables: lead_conversations, lead_notes
  │   Data created: transcripts, AI suggestions, applied actions
  │
  ▼
FEE PROPOSAL
  ├── Fee proposal created from Buildexact estimate
  │   Tables: fee_proposals, buildexact_estimates
  │   Data created: structured cost breakdown, PDF, Dropbox path
  │   AI: Buildexact XLSX/PDF parsed, DOCX template filled
  │   External: Buildexact (source), Google Drive (edit), Dropbox (store), Gmail (send)
  │
  ▼
TENDER
  ├── Job created / imported from Buildexact
  │   Tables: jobs (with lead_id FK)
  │   Data created: address, description, trade scopes, areas
  │   External: Buildexact (job lookup)
  │
  ├── Blueprints / docs uploaded to Dropbox
  │   Tables: rfqs (doc references)
  │   External: Dropbox
  │
  ├── AI extracts RFQ scopes from documents
  │   Tables: rfqs, rfq_trade_scopes
  │   AI: Claude extracts trade scope items from blueprints/specs
  │
  ├── RFQ Packages created and sent to subcontractors
  │   Tables: rfq_packages, rfq_trade_scopes, rfq_recipients, rfq_addenda
  │   External: Gmail/SMTP (send), Dropbox (attach docs)
  │
  ├── Quotes returned and matched
  │   Tables: rfqs (quoted_amount, quote_extraction), unmatched_quote_emails
  │   External: IMAP (inbound email), Dropbox (PDF storage)
  │
  ▼
WIN / LOSS DECISION
  ├── Tender Board: compare quotes, decide
  │   Tables: jobs (won_at, lost_at, outcome fields)
  │   External: Buildexact (status sync)
  │
  ├── ON WIN:
  │   ├── Project created from Job
  │   │   Tables: projects (job_id FK, portal_token generated)
  │   ├── PO issued to preferred subcontractors
  │   │   Tables: purchase_orders
  │   │   External: Gmail (PO email), Dropbox (PO PDF)
  │   └── Job address synced to Project (trigger migration 036)
  │
  ▼
OPERATIONS
  ├── Project appears in Operations list
  │   Tables: projects (with schedule_tasks JOIN for health metrics)
  │
  ├── Schedule generated by AI
  │   Tables: schedule_tasks, schedule_templates
  │   AI: Claude generates tasks from description + template
  │   Data created: tasks with phase, trade, dates, dependencies, procurement
  │
  ├── Baseline locked
  │   Tables: schedule_tasks (baseline_start_date, baseline_end_date), projects (schedule_baseline_locked_at)
  │
  ├── Delays tracked
  │   Tables: schedule_eot
  │   Data created: reason code, days claimed, approval status
  │
  ▼
WHS COMPLIANCE
  ├── Subcontractor compliance docs uploaded
  │   Tables: contractor_compliance
  │
  ├── SWMS uploaded and linked
  │   Tables: swms_templates, project_swms
  │
  ├── Site inductions via QR code
  │   Tables: site_inductions
  │   Public endpoint: /induct/:projectId (no auth)
  │
  ├── Incidents logged
  │   Tables: site_reports (type: incident)
  │
  ▼
SITE DIARY
  ├── Daily entries
  │   Tables: site_diary
  │   AI: Voice → structured text (Claude)
  │   Data created: date, weather, trades on site, progress notes, delays
  │
  ▼
FINANCE
  ├── Invoices received (email or upload)
  │   Tables: financial_documents, financial_approvals
  │   AI: Claude extracts supplier, amount, trade, description from PDF/image
  │   External: IMAP, Dropbox
  │
  ├── Matched to Job + Trade Category
  │   Tables: financial_documents (job_id, trade_category_id)
  │   Tables: trade_categories (37 Buildxact master categories)
  │
  ├── Approved and filed
  │   Tables: financial_approvals
  │   Planned: Xero sync
  │
  ▼
JOB COMMAND CENTRE
  ├── Budget vs committed vs invoiced per trade
  │   Tables: job_budgets, financial_documents
  │   Data: budget (from Buildexact), committed (POs), invoiced (approved invoices)
  │
  ├── Progress claims (WIPAA)
  │   Tables: progress_claims, progress_claim_payments
  │   Data: claim schedule, % claimed, payment records
  │
  ├── Variations (change orders)
  │   Tables: job_variations
  │   Trigger: signed variations update jobs.contract_value (migration 034)
  │
  ▼
CLIENT PORTAL
  ├── Weekly updates shared with client
  │   Tables: portal_updates (text, video_url)
  │
  ├── Progress photos
  │   Tables: project_photos
  │
  ├── Milestones celebrated
  │   Tables: portal_milestones
  │
  ├── Decisions required from client
  │   Tables: portal_decisions, portal_allowances, home_finishes
  │
  ├── Budget view (controlled visibility)
  │   Tables: portal_claims (client-facing progress claims)
  │
  ├── Messages
  │   Tables: portal_messages
  │
  ├── Site walk bookings
  │   Tables: site_walks
  │
  ├── Warranty period tracking
  │   Tables: warranty_items, warranty_periods
  │
  └── Email delivery tracking
      Tables: email_delivery_events (open pixel, portal view)
```

## Key Data Creation Points

| Data | Created by | Stored in |
|------|-----------|-----------|
| Lead | User (Sales Pipeline) | `leads` |
| Job/Tender | Buildexact import or manual | `jobs` |
| RFQ scopes | Claude AI extraction | `rfqs`, `rfq_trade_scopes` |
| Fee proposal | Buildexact parse + user edit | `fee_proposals` |
| Project | Auto-created on win | `projects` |
| Schedule tasks | Claude AI generation | `schedule_tasks` |
| Invoices | Email/upload + AI extraction | `financial_documents` |
| Progress claims | User (Job Command Centre) | `progress_claims` |
| Variations | User (Job Command Centre) | `job_variations` |
| Portal updates | Admin/supervisor | `portal_updates` |
| Site diary | Supervisor (voice/text) | `site_diary` |
| Inductions | Visitor (public form) | `site_inductions` |

---

## Data That Flows Automatically (No Re-entry)

| Trigger | Effect |
|---------|--------|
| Job marked Won | Project record created |
| `jobs.address` updated | `projects.address` synced (trigger) |
| Variation signed | `jobs.contract_value` updated (trigger) |
| Schedule task saved | `trade_master_id` backfilled by trade slug (migration 038) |
| Subcontractor saved | `trade_category_id` backfilled by trade name pattern (migration 040) |
| RFQ package saved | `job_id` required (migration 039) |

---

## External Data Sources

| Source | What it provides | How imported |
|--------|-----------------|--------------|
| Buildexact | Job details, cost estimates, categories | API pull + XLSX/PDF parse |
| Email (IMAP) | Subcontractor quotes | Auto-matched by IMAP polling |
| Email (IMAP) | Supplier invoices | Auto-matched or queued |
| Dropbox | Blueprint PDFs, specs | User uploads then AI extracts |
| Client (portal) | Decisions, allowance selections | Client-facing portal |

## Reporting Data

| Report | Source Tables | Available |
|--------|--------------|-----------|
| Schedule health | `schedule_tasks` (percent_complete, end_date) | Yes |
| Trade conflicts | `schedule_tasks` (assignee_trade, dates across projects) | Yes |
| Procurement alerts | `schedule_tasks` (procurement_order_by) | Yes |
| Budget vs actual | `job_budgets` vs `financial_documents` | Yes |
| Margin tracking | `jobs` (contract_value, estimated_total_cost, progress_billed) | Yes |
| Cost benchmarks | `cost_benchmarks`, `normalized_costs` | Partial |
| WHS compliance | `contractor_compliance`, `site_inductions` | Yes |
| Lead conversion | `leads` (won_at, lost_at, stage) | Yes |
