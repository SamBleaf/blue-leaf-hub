# SOP: Install the Worker app on an iPhone home screen

**Module:** Workforce
**SOP ID:** 10-02
**Status:** Draft
**Priority:** Medium

---

## 1. Who uses this
- Field workers / tradies ("the guys") on iPhone
- Admin (to generate and send the worker link)

## 2. When to use it
When a worker should have the Blue Leaf timesheet & task app as a tappable icon on their iPhone home screen (instead of opening a browser link each time).

## 3. What this does
Turns the worker web app into a home-screen app on iPhone. After installing, the worker taps the Blue Leaf leaf icon and the app opens full-screen — no Safari address bar — straight to their timesheet, using the magic link they were sent (no password).

## 4. Before you start
- The worker must have been sent their personal worker link by an admin (Workforce → Team → **Worker link**). The link looks like `https://<hub-domain>/worker?token=…`.
- They must open it in **Safari** on iOS (Add to Home Screen is a Safari feature — Chrome on iOS cannot do it).
- No login or App Store account is needed.

## 5. Step-by-step process

1. On the worker's iPhone, open the **worker link** in **Safari** (tap it from the SMS/WhatsApp message the office sent).
2. The app loads on the **timesheet home** screen, with a one-time banner: *"To install: tap the Share button … then Add to Home Screen."*
3. Tap the **Share** button (the square with an up-arrow) at the bottom of Safari.
4. Scroll down and tap **Add to Home Screen**.
5. Leave the name as **Blue Leaf Building**, tap **Add** (top right).
6. A blue Blue Leaf **leaf icon** now sits on the home screen. Tap it — the app opens full-screen.

> 💡 **Tip:** The token is remembered after the first open, so the home-screen icon goes straight to the worker's own timesheet every time — they never re-enter the link.

## 6. What happens next
The worker now opens the app from the icon like any other app. It launches full-screen (standalone), shows their timesheet and site tasks, and works for logging hours, viewing the month calendar, and completing tasks. Nothing is created in the database by installing — install is purely a device action.

## 7. Common mistakes

| Mistake | Why it happens | How to avoid it |
|---------|---------------|-----------------|
| Opening the link in Chrome/another browser | Only Safari has "Add to Home Screen" on iOS | Tell the worker to open the link in Safari |
| Icon looks blank/distorted | Old cached icon from before this release | Remove the icon and re-add it after the release is live |
| Worker re-sent a new link later but old icon opens an expired token | Admin rotated the token | Send the new link; the worker removes the old icon and re-adds from the new link |

## 8. Troubleshooting

| Problem the user sees | Most likely cause | Fix |
|----------------------|-------------------|-----|
| No "Add to Home Screen" option | Link opened in a non-Safari browser | Re-open the link in Safari |
| App opens with the Safari address bar still showing | Added a plain bookmark, or opened the icon before install finished | Remove and re-add via Share → Add to Home Screen |
| Top of the blue header is cut off under the notch | Old build before safe-area padding | Confirm the current release is deployed; hard-refresh once |
| Tapping the icon shows the login page, not the timesheet | The worker token wasn't in the link they used | Re-send the `/worker?token=…` link and re-add the icon |

## 11. Automation notes
- No database records are created or changed by installing (device-only action).
- The app icons are generated by `scripts/generate-pwa-icons.mjs` from `public/brand/social-icon-blue.jpg` into `public/icons/` (icon-192.png, icon-512.png, apple-touch-icon.png) and committed.
- Worker identity is served by `worker.html` → `/manifest.json` (start_url `/worker`, display standalone); the Hub identity is `index.html` → `/manifest.webmanifest`.
- The service worker (Workbox, production mode) precaches the app shell so the icon launches instantly; API/data still require a connection.

## 12. Edge cases and limits
- iOS only honours square PNG icons (it ignores SVG) — that is why raster PNGs are generated.
- Re-running `scripts/generate-pwa-icons.mjs` reproduces identical icons (idempotent); commit the PNGs so the Vercel build does not need macOS `sips`.
- The worker app is currently **online-only** — installing it does not make timesheet logging work offline.
- Android shows an automatic "Install" button instead of the manual iOS steps; the same icons are used.

## 14. Troubleshoot Agent Test Script

> **For the troubleshoot agent only.** Run every test in order on a production build (PWA features are off in `npm run dev`). Record pass/fail. Document any failure in SOP_CHANGELOG.md.

| TC | What to test | Steps | Expected result |
|----|--------------|-------|-----------------|
| TC-01 | Icons exist and are square | After `npm run build`, check `dist/icons/` | `icon-192.png` (192×192), `icon-512.png` (512×512), `apple-touch-icon.png` (180×180) all present and square |
| TC-02 | Both entry HTMLs carry the iOS icon | Inspect `dist/index.html` and `dist/worker.html` | Both contain `<link rel="apple-touch-icon" href="/icons/apple-touch-icon.png">` and the `apple-mobile-web-app-*` meta tags |
| TC-03 | Manifests reference PNG icons | Inspect `dist/manifest.json` (worker) and `dist/manifest.webmanifest` (hub) | Icons point at `/icons/icon-192.png` + `/icons/icon-512.png`, `type: image/png`, purpose `any maskable` — no SVG icons remain |
| TC-04 | Production service worker | Inspect build log / `dist/sw.js` | Build reports `mode generateSW`; `dist/sw.js` + `workbox-*.js` generated; `workbox.mode` is `production` in `vite.config.js` |
| TC-05 | Static icon serves (not SPA fallback) | On the deployed site, request `/icons/icon-192.png` | Returns HTTP 200 with `Content-Type: image/png` (NOT `text/html` from the SPA catch-all) |
| TC-06 (feature) | iOS install is clean | On a physical iPhone (notch/Dynamic Island), open `/worker?token=…` in Safari → Share → Add to Home Screen → launch | Icon is the BLB blue leaf, square and undistorted; app launches full-screen (no Safari chrome); the blue header sits **below** the status bar / Dynamic Island (not clipped) |
| TC-07 (feature) | Icon generator is reproducible | Run `node scripts/generate-pwa-icons.mjs` twice | Both runs print 192/512/180 dimensions and produce valid PNGs without error |
